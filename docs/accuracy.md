# 정확도

피드백마다 정답을 붙여 잰 「맞는 비율」(찾은 것 중 맞은 것). 80% 를 넘어야 리포트에 나온다(`--preview` 제외). 「모르겠다」는 계산에서 뺀다.

## 재는 법

1. `node scripts/make-labeling.mjs [일수] [이전 판정 파일]` — 지금 규칙으로 찾은 것을 정답 붙이기 페이지(`~/.ai-dev-feedback/label.html`)로 만든다. 이전 판정을 주면 바뀌지 않은 항목은 그 답을 다시 쓰고, 새로 판정할 것만 보여 준다.
2. 브라우저에서 항목마다 「맞다 / 아니다 / 모르겠다」를 누르고, 아니라면 까닭을 한 줄 적는다. 「결과 저장」으로 판정 파일을 내려받는다.
3. `node scripts/score-labels.mjs [판정 파일]` — 피드백별 맞는 비율을 `docs/accuracy.json` 에 쓴다.

사람 뜻이 필요한 것(「같은 문제였나」, 「늘 지킬 규칙을 말한 것인가」)은 기록의 주인이 판정한다. 코드를 보면 판단되는 것(테스트에 결과 확인이 있나)과 내용을 보이면 안 되는 것(비밀값)은 만든 사람이 확인한다.

## 지금 값의 성격 — 개발용

`docs/accuracy.json` 의 값은 **만든 사람의 기록 한 달치로 판정하고, 틀린 것을 보고 규칙을 고친 뒤 같은 기록으로 다시 잰 개발용 값**이다. 실제보다 후하게 나온다.

- 진짜 검증은 고친 뒤에 생긴 기록이나 다른 사람의 기록으로 한다. 그 결과가 80% 를 못 넘으면 그 피드백은 다시 숨긴다.
- 놓친 것(재현율)은 아직 재지 않았다.

## 판정에서 배워 고친 것

- **「고쳐 줘」 반복**: 처음엔 연달아 온 수정 요청을 모두 잡아, 서로 다른 작은 요청이나 시험하며 적은 여러 문제까지 「같은 증상 반복」으로 셌다. → 구간마다 「같은 문제인가」(고친 뒤에도 같은 증상이 남았나, 모르면 다르다고 본다)를 묻고 같은 문제인 가장 긴 연속 부분만 남긴다. 작은 모델은 거의 모두 「같다」고 답해 걸러 내지 못해서 큰 모델로 묻는다. 그만큼 놓치는 것도 생긴다 — 거짓 경보보다 놓치는 쪽을 택했다.
- **같은 부탁 반복**: 처음엔 그 작업에만 한 지시(「이번엔 ~하지 마」)를 늘 지킬 규칙으로 읽었다. → 일반화 기준을 「앞으로 에이전트의 행동을 바꾸라는 말」로 좁히고, 묶은 뒤 메시지마다 그 규칙에 다시 대 보는 단계를 더했다.
- **같은 부탁 반복**: 모델이 「규칙 아님」을 '-' 대신 긴 줄표(—)로 답해, 규칙이 아닌 메시지들이 「—」라는 규칙으로 묶였다. → 줄표·「없음」 답을 모두 「규칙 아님」으로 본다.
