# 근거 표 — AI 개발 능력을 기르는 피드백

2026-10-02 작성, 같은 날 정리. 네 갈래(연구·조사 / 도구 회사 지침 / 국내외 기업 테크블로그 / 피드백·학습 연구)로 모은 것을 합쳤다. 테크블로그는 국내외를 가리지 않는다. 출처를 고르는 기준은 나라가 아니라 근거의 무게·최신성·도구와 상관없는가다.

이 문서가 정하는 것: **어떤 피드백을, 어떤 근거로 줄 것인가.** 피드백을 어떻게 보여 주는지는 `design.md`.

## 읽는 법

- **등급**: A 통제 실험·메타분석·대규모 논문 / B 대규모 조사·관찰 / C 도구 회사 지침 / D 기업 경험담
- **확인**: ✔ 원문에서 직접 대조함(날짜) / ○ 조사 에이전트가 원문을 열었다고 보고(요약 모델 경유) / △ 검색 요약만
- **사용자에게 보이는 문장은 ✔ 만 인용한다.** 2026-10-02 대조에서 요약만 본 출처 3곳(Stripe·토스·Tang)이 원문과 어긋났다. ○·△ 는 설계 판단의 참고로만 쓴다.

## 공통으로 인정하는 조건

1. **서로 독립된 출처 두 곳 이상**이 같은 말을 한다. 같은 회사 문서 여럿은 한 곳으로 친다.
2. 그중 하나는 연구(A·B)이거나, **서로 다른 도구 회사 두 곳 이상**이다. 경험담끼리만 맞는 것은 유행일 수 있다.
3. 겉으로만 갈리는 것(결과 변수가 다른 연구 등)은 겹치는 부분만 살린다.
4. 「다음에는」 문구는 도구와 상관없이 **사용자가 할 행동**으로 쓴다(예: 「모델에게 스스로 검증시켜라」 ✗ → 「결과 하나는 직접 확인하라」 ✔). 모델에 따라 뒤집히는 조언을 피하기 위해서다.

| # | 규칙 | 근거 | 등급·확인 |
|---|---|---|---|

## 3. 보류 — 근거가 한 곳뿐이거나 측정이 애매함

| 후보 | 까닭 | 풀리는 조건 |
|---|---|---|
| 세션 뒤로 갈수록 위임이 늘어남(점진 의존) | 실험 하나, 해당 유형 n=4 | 같은 결과의 다른 연구 |
| 오류 끄기(`@ts-ignore`, `eslint-disable`, 빈 catch, `--no-verify`) | 도구 지침 한 곳(Claude Code 「root cause, don't suppress」) | 다른 회사 지침이나 연구 |
| 돈·권한·저장 형식 로직은 명세 → 승인 → 테스트 목록 → 승인 → 구현 | 우아한형제들 한 곳 | 다른 사례 |
| 출력을 확인 없이 받아들임 | 근거가 자기보고 설문(Lee CHI 2025), 사소한 변경과 구분이 어려움 | 측정 방법을 찾으면 |
| 지침 파일 크기 | 「짧게」는 공통(CC·Codex·Copilot)이지만 몇 토큰부터 문제인지는 근거 없음(토스 글의 500~2,000 은 권장이 아닌 추정치) | 그래서 크기 자체가 아니라 C13(규칙이 묻혀 어겨짐)으로 짚는다 |
| 버그 수정 커밋에 원인을 직접 적었나 | 토스 한 곳 | — |

| 계획 모드부터 | CC·Cursor·Gemini 권장 vs Codex 하네스 제작자용 지침은 조기 종료 위험 |
| 서브에이전트 | CC 는 조사를 맡기라, 같은 회사 프롬프트 지침은 Opus 4.6·5 남용 경고 |
| 권한 설정 세부 | 도구마다 방식이 다름(원칙인 「파괴적 명령은 확인」만 C14 에 남김) |

기록에는 모델·버전·effort·권한 모드를 계속 남긴다(비용 없음). 1차에서는 쓰지 않는다.

## 5. 제외 — 근거가 반대함

| 쓰지 않을 것 | 까닭 |
|---|---|
| 속도·처리량(작업 시간, PR 수, 줄 수, AI 사용량) | F16. 체감과 실측이 반대, PR 수는 쪼갠 횟수일 수 있음 |
| 연속 기록·점수·순위 | F11 |
| 「AI 를 덜 써라」 | 이해하며 쓰면 실력이 지켜짐(Shen & Tamkin). 「얼마나」가 아니라 「어떻게」 |
| 「2배·10배」, 「AI 코드 75%」 같은 수치 | 측정 방법 없음, 자기보고, 공급사 행사 발표 |
| 설명 강제(막는 방식) | F14 |
| 정할 때 이유를 붙였나(code-dependent 에 넣은 것) | 이 도구의 근거 어디에도 직접 나오지 않음. 재미용 거울에만 둔다 |

## 6. 서로 충돌하는 결과 — 남긴 것의 근거

- **AI 가 학습을 해치나 돕나**: Shen & Tamkin·Wu(해침) vs Contractor & Reyes(전체로는 도움). 셋 다 「설명을 구하면 남고, 대신 시키면 사라진다」로 일치 → C1.
- **빨라지나**: METR 2025 −19% / METR 2026 가속 쪽이나 신뢰구간이 0 포함 / Microsoft PR +24% / Cursor 도입 첫 달 급증 후 복귀 → F16.
- **지침 파일이 돕나**: Gloaguen 2026(성공률 이득 없음, 비용 +20%) vs Denisov-Blanch 2026(성숙한 설정은 품질 비용 절반) → 결과 변수가 다름. 「짧게, 규칙만, 실수 나오면 갱신」이 둘 다와 맞음 → C12·C13.
- **에이전트 PR 쓸 만한가**: Watanabe(Claude Code PR 83.8% 병합) vs METR 2026(테스트 통과 PR 약 절반 거절) → 사람이 고른 것 vs 자동 결과 그대로.

## 7. 아직 없는 근거 — 도구가 직접 잴 것

- 「가설을 먼저 세우면 에이전트 환경에서 나아진다」 직접 실험 → 약속을 지킨 때와 안 지킨 때 걸린 시간 비교
- 「작업 중 알림 vs 사후 회고」를 AI 코딩에서 비교한 실험 → 알림을 무작위로 켜고 끄며 비교
- Huang 2025 의 세부 숫자(프롬프트당 1.8단계, 13명 중 9명 전부 검토)는 본문 미확인이라 인용하지 않는다
